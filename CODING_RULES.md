# Coding Rules

These rules apply to ALL code written in this project. Reference this file before every coding task.

## Rules

1. Always follow industry-standard patterns, conventions, and idioms for the specific language and framework being used.

2. Implement only what is explicitly requested without adding extra functionality, abstractions, or features unless specifically asked.

3. Write clear, readable code with meaningful names, focused functions, and necessary comments for complex logic only.

4. Maintain consistency with existing project code style, formatting conventions, error handling patterns, and input validation approaches.

5. Import only necessary libraries and dependencies that are justified by the actual requirements, avoiding bloat.

6. Create modular, reusable code units that avoid duplication while maintaining logical separation of concerns.

7. Write testable code with clear interfaces and include basic test cases or usage examples when requested.

8. Add concise docstrings for public functions/classes and provide usage examples only when specifically asked.

9. Follow basic security best practices for the context and write efficient code while prioritizing clarity over premature optimization.

10. Respect project-specific guidelines, architecture, and technology stack without changing interfaces or data models unless explicitly specified.

11. No file should exceed 500 lines of code. If it does, refactor the code into smaller, manageable modules or classes to enhance readability and maintainability.

12. Do not add any unnecessary comments.
